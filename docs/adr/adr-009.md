# ADR 0009: Zotero-Integration über dateibasierte Bibliografie (.bib)

**Status:** Akzeptiert
**Kontext:**
Für wissenschaftliche Arbeiten und Manuskripte benötigt Rosida eine reibungslose Literaturverwaltung. Da der finale Export über Quarto abgewickelt wird, ist die native Pandoc-Unterstützung für Bibliografien ohnehin gesetzt. Eine direkte, harte Kopplung an Zoteros interne SQLite-Datenbank oder Web-API würde die Architektur unnötig verkomplizieren, Abhängigkeiten schaffen und die auf einfachen Textdateien basierende Autarkie (SDI-Prinzip) des Werkzeugs untergraben.

**Entscheidung:**
Die Integration von Literaturquellen wird strikt dateibasiert und dezentral über Standardformate gelöst.

* **Datenhaltung:** Eine `.bib`-Datei (BibTeX) im jeweiligen Projektverzeichnis (neben der `.qmd`-Datei) dient als einzige Datenquelle.
* **UI-Komponente:** Ein neues `QDockWidget` ("Literatur") überwacht und parst diese `.bib`-Datei.
* **Darstellung:** Das Dock verwendet eine Listen- oder Tabellenansicht (`QTreeWidget` oder `QTableView`) mit den Spalten: *Kürzel (Citekey)*, *Autor* und *Titel*.
* **Detailansicht:** Ein Tooltip (Mouse-Hover) über einem Eintrag zeigt den vollständigen, ungekürzten Titel sowie ggf. das Jahr an.
* **Interaktion:** Ein Doppelklick auf einen Eintrag fügt die formatierte Referenz (z. B. `[@citekey]`) exakt an der aktuellen Cursorposition des aktiven Editors ein.

**Konsequenzen:**

* **Positiv:** Maximale Robustheit. Rosida bleibt vollständig entkoppelt von Zotero. Das Parsen einer Textdatei ist rasend schnell und fehlerunanfällig.
* **Positiv:** Perfekte Quarto-Synergie. Die `.bib`-Datei kann direkt im YAML-Header des Dokuments (`bibliography: referenzen.bib`) für den finalen Build verwendet werden.
* **Voraussetzung:** Der Workflow erfordert, dass die `.bib`-Datei im Projektordner aktuell gehalten wird (idealerweise durch den "Auto-Export" des Better BibTeX Plugins in Zotero).
