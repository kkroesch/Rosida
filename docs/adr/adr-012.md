# ADR 0012: Visuelle Organisation von Literatur-Notizen (Denkbrett / Post-it UI)

**Status:** Akzeptiert
**Kontext:**
Für die Strukturierung wissenschaftlicher Manuskripte und großer Buchprojekte reicht eine flache Listenansicht der Literatur-Notizen (Zettelkasten) oft nicht aus. Ein räumliches, visuelles Ordnen (analog zum "Denkbrett" in Papyrus Autor) unterstützt den kreativen Schreibprozess erheblich. Eine klassische Implementierung würde die Koordinaten der Post-its in einer zentralen, proprietären UI-Datenbank speichern. Das widerspricht jedoch Rosidas architektonischem Kernprinzip: Der Nutzer muss absolute Souveränität über seine Daten behalten (Plain-Text-Paradigma, kein Vendor-Lock-in).

**Entscheidung:**
Die visuelle Organisationsebene wird vollständig zustandslos implementiert, indem die UI-Metadaten in den bestehenden Markdown-Dateien serialisiert werden.

* **UI-Komponenten:** Die Zeichenfläche wird über Qt's `QGraphicsView` und `QGraphicsScene` in einem eigenständigen Fenster realisiert. Notizen werden als interaktive, verschiebbare `QGraphicsItem`-Objekte (Kärtchen/Post-its) gerendert.
* **Datenspeicherung:** Die räumlichen Koordinaten und visuellen Eigenschaften (z. B. Farbe) werden als Standard-Variablen im YAML-Frontmatter der jeweiligen Zettelkasten-Markdown-Datei gespeichert:
```yaml
---
citekey: taleb2012
title: Antifragile
board_x: 450
board_y: 120
color: yellow
---

```


* **Synchronisation:** Wird ein Kärtchen auf der Zeichenfläche verschoben, aktualisiert Rosida im Hintergrund (via abstrahiertem I/O-Handler) ausschließlich den YAML-Block der entsprechenden `.md`-Datei, ohne den Body-Text anzutasten.

**Konsequenzen:**

* **Positiv:** Antifragile Datenhaltung. Die Zettelkasten-Dateien bleiben völlig autark und können weiterhin nativ in Neovim, Obsidian oder über Shell-Skripte (`rg`, `fzf`) verarbeitet werden.
* **Positiv:** Keine zusätzlichen Abhängigkeiten oder relationale Datenbanken für den UI-Zustand. Die Markdown-Datei ist die "Single Source of Truth".
* **Negativ/Trade-off (I/O-Last):** Da jede Bewegung auf dem Board zu einem Datei-Schreibvorgang führt, muss zwingend ein *Debouncing* (z. B. via `QTimer`) implementiert werden. Es wird erst gespeichert, wenn das Kärtchen losgelassen wurde oder eine halbe Sekunde unbewegt bleibt, um unnötigen I/O-Overhead zu vermeiden.
